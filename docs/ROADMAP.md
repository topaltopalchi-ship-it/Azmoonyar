# نقشه راه آزمون‌یار

## مرحله ۰ — دامنه و معیارهای آزمایش
- [x] تعیین نام و جهت‌گیری آفلاین‌محور.
- [x] تعریف رفتار محافظه‌کارانه برای علامت‌های مبهم.
- [ ] تثبیت قالب چاپی پاسخنامه و نمونه آزمایشی.
- [ ] ساخت مجموعه آزمایشی برچسب‌گذاری‌شده با شرایط متنوع.

## مرحله ۱ — پایه اندروید
- [ ] ساختار پروژه اندروید و بیلد قابل تکرار Gradle.
- [ ] پوسته رابط فارسی RTL و ناوبری قابل دسترس.
- [ ] پایگاه داده محلی و نسخه‌بندی schema.
- [ ] تعریف آزمون، کلید پاسخ، نمره‌دهی و شناسه دانش‌آموز/برگه.
- [ ] آزمون‌های واحد برای نمره‌دهی و اعتبارسنجی.

## مرحله ۲ — دوربین و OMR
- [ ] ثبت تصویر دوربین با راهنمای هم‌ترازی و کنترل کیفیت.
- [ ] اصلاح پرسپکتیو و تشخیص جایگاه پاسخنامه.
- [ ] تشخیص حباب خالی، پرشده و مبهم.
- [ ] آستانه اطمینان و صف بازبینی دستی.
- [ ] تشخیص برگه تکراری و شناسه آزمون ناشناخته.
- [ ] نگهداری تصویر اصلی و سابقه اصلاحات.

## مرحله ۳ — نتایج
- [ ] جدول نتایج و خلاصه آزمون.
- [ ] گردش کار بازبینی و اصلاح.
- [ ] خروجی CSV/XLSX و PDF به‌صورت محلی.
- [ ] پشتیبان‌گیری و بازیابی با کنترل صریح کاربر.

## مرحله ۴ — اعتبارسنجی و انتشار
- [ ] آزمایش روی گوشی‌ها، دوربین‌ها، نورها و چاپ‌های متفاوت.
- [ ] اندازه‌گیری دقت هر سؤال، دقت کل برگه و نرخ بازبینی.
- [ ] آزمون رگرسیون برای تغییرات الگوریتم تشخیص.
- [ ] ساخت و بررسی APK/AAB امضاشده انتشار؛ بیلد debug را نسخه انتشار معرفی نکنیم.

## مرحله ۵ — نسخه ویندوز
- [ ] استفاده مجدد از قواعد نمره‌دهی و مدل داده مستندشده.
- [ ] پشتیبانی از دوربین یا واردکردن تصویر/PDF.
- [ ] اجرای آفلاین تشخیص و نمره‌دهی.
- [ ] بررسی سازگاری خروجی/ورودی بین اندروید و ویندوز.

## شرط تکمیل هر مرحله
صرفاً سبز شدن کامپایل به معنی تکمیل قابلیت نیست. آزمون خودکار، آزمایش دستی و شواهد قابل بررسی لازم‌اند. هر ادعای دقت باید اندازه و شرایط مجموعه آزمایشی را بیان کند.
