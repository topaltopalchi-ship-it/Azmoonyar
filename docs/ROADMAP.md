# نقشه راه آزمون‌یار

## مرحله ۰ — دامنه و معیارهای آزمایش
- [x] تعیین نام و جهت‌گیری آفلاین‌محور.
- [x] تعریف رفتار محافظه‌کارانه برای علامت‌های مبهم.
- [x] ثبت نیازمندی اسکن زنده و خودکار بدون دکمه عکس‌گرفتن.
- [ ] تثبیت قالب چاپی پاسخنامه و نمونه آزمایشی.
- [ ] ساخت مجموعه آزمایشی برچسب‌گذاری‌شده با شرایط متنوع.

## مرحله ۱ — پایه اندروید
- [x] ساختار اولیه پروژه اندروید و بیلد خودکار آزمایشی.
- [x] رابط فارسی اولیه.
- [x] تعریف آزمون، تعداد سؤال و ثبت کلید پاسخ در حافظه محلی.
- [x] افزودن وابستگی‌های CameraX و QR decoder آفلاین.
- [ ] پایگاه داده محلی نسخه‌دار و مدل کامل شرکت‌کننده/برگه.\n- [x] نمونه اولیه ثبت فهرست شرکت‌کنندگان به‌صورت آفلاین با شناسه یکتای داخلی (هنوز به QR و چاپ متصل نیست).
- [x] هستهٔ مستقل قواعد نمره‌دهی و آزمون‌های واحد (هنوز به جریان اسکن/نتایج متصل نشده است).

## مرحله ۲ — طراحی آزمون داخل برنامه
- [ ] افزودن بخش «ساخت آزمون» با دو روش ورود سؤال: تایپ متن و افزودن عکس از دوربین/گالری.
- [ ] پشتیبانی از متن سؤال، گزینه‌ها، پاسخ صحیح، نمره و توضیح اختیاری.
- [ ] پشتیبانی از سؤال تصویری: تصویر می‌تواند عکس صفحه کتاب، نمودار، فرمول یا شکل باشد؛ تصویر در پیش‌نمایش و خروجی چاپی حفظ شود.
- [ ] ابزارهای پایه تصویر: برش، چرخش و تنظیم محدوده؛ OCR و استخراج خودکار متن قابلیت جداگانه و غیرالزامی است.
- [ ] امکان ترکیب سؤال متنی و تصویری در یک آزمون و جابه‌جایی ترتیب سؤال‌ها.
- [ ] پیش‌نمایش برگه پیش از چاپ و تولید پرسشنامه PDF با صفحه‌بندی قابل خواندن.
- [ ] تولید کلید تصحیح و پاسخنامه استاندارد هماهنگ با همان آزمون.
- [ ] ثبت قالب هر آزمون برای پیوند دادن پاسخ‌ها به سؤال‌ها؛ تصویر سؤال به‌تنهایی برای تشخیص حباب پاسخ استفاده نشود.
- [ ] نگهداری محلی پیش‌نویس‌ها و امکان ویرایش/حذف با تأیید کاربر.

## مرحله ۳ — اسکن زنده و OMR
- [x] پیش‌نمایش پیوسته دوربین با CameraX؛ بدون نیاز به فشردن شاتر.
- [x] تحلیل فریم‌ها در حافظه و خواندن QR آفلاین.
- [x] ثبت شناسه یکتا و جلوگیری از ثبت تکراری در همان آزمون.
- [ ] تولید QR و قالب استاندارد پاسخنامه از داخل برنامه.
- [ ] تشخیص زنده گوشه‌ها/نشانه‌های برگه و اصلاح پرسپکتیو.
- [ ] کنترل وضوح، نور و ثابت‌ماندن برگه؛ فقط پس از عبور از کنترل کیفیت پردازش خودکار شود.
- [x] پردازش فریم دوربین در حافظه؛ تصویر دائمی ذخیره نمی‌شود.
- [x] افزودن طبقه‌بند محافظه‌کار جاوا برای امتیازهای چهار حباب: خالی، تک‌پاسخ، چندعلامتی و نیازمند بازبینی (هنوز به تصویر دوربین/تشخیص هندسه متصل نیست).
- [ ] اتصال امتیازدهی حباب به تصویر پس از تشخیص گوشه‌ها، اصلاح پرسپکتیو و نرمال‌سازی نور.
- [ ] جلوگیری از ثبت دوباره پاسخنامه پس از اتصال OMR به شناسه.
- [ ] صف بازبینی دستی و امکان اسکن مجدد.
- [ ] پشتیبانی از پاسخنامه جداگانه و پاسخ‌های حبابی روی خود پرسشنامه.
- [ ] برای چیدمان معلم‌ساخته، جریان تعریف/تأیید قالب و نگاشت حباب‌ها؛ تشخیص خودکار همه چیدمان‌های دلخواه تضمین نسخه اول نیست.

## مرحله ۴ — نتایج

- [ ] جدول نتایج و خلاصه آزمون.

- [ ] پشتیبان‌گیری و بازیابی با کنترل صریح کاربر.

## مرحله ۵ — اعتبارسنجی و انتشار
- [ ] اجرای موفق بیلد CI و بررسی گزارش خطاها.
- [ ] آزمایش روی گوشی‌ها، دوربین‌ها، نورها و چاپ‌های متفاوت.
- [ ] اندازه‌گیری دقت هر سؤال، دقت کل برگه و نرخ بازبینی.
- [ ] آزمون رگرسیون برای تغییرات الگوریتم تشخیص.

## مرحله ۶ — نسخه ویندوز
- [ ] استفاده مجدد از قواعد نمره‌دهی و مدل داده مستندشده.
- [ ] پشتیبانی از دوربین یا واردکردن تصویر/PDF.
- [ ] اجرای آفلاین تشخیص و نمره‌دهی.
- [ ] بررسی سازگاری خروجی/ورودی بین اندروید و ویندوز.

## شرط تکمیل هر مرحله
صرفاً سبز شدن کامپایل به معنی تکمیل قابلیت نیست. آزمون خودکار، آزمایش دستی و شواهد قابل بررسی لازم‌اند. هر ادعای دقت باید اندازه و شرایط مجموعه آزمایشی را بیان کند.


## پیاده‌سازی اخیر: ثبت شرکت‌کننده و چاپ QR مشترک

- [x] ثبت آفلاین شرکت‌کننده با شناسهٔ داخلی یکتا.
- [x] نمونهٔ اولیهٔ چاپ از طریق قابلیت چاپ اندروید: یک صفحهٔ A4 شامل بخش «برگهٔ سؤال» و «پاسخنامه» با QR یکسان برای همان شرکت‌کننده و آزمون.
- [ ] اتصال خروجی چاپ به سازندهٔ واقعی برگهٔ سؤال و پاسخنامه؛ فعلاً صفحهٔ چاپ، برگهٔ همراهِ QR است و جایگزین برگهٔ کامل آزمون نیست.
- [ ] اجرای build و آزمایش چاپ روی دستگاه واقعی؛ تا پیش از این آزمایش، موفقیت build/چاپ تأییدشده نیست.

قالب QR فعلی با اسکنر موجود سازگار است: `AZY1|نام دقیق آزمون|شناسه یکتای شرکت‌کننده`. نام شرکت‌کننده برای نمایش چاپ می‌شود؛ شناسهٔ داخلی، کلید تطبیق است. اگر دو شرکت‌کننده نام یکسان داشته باشند، شناسه‌های متفاوتشان مانع یکی‌شدن رکوردها می‌شود.

## مرحله ۴A — گزارش‌دهی آفلاین و حریم خصوصی

- [x] افزودن مخزن محلی گزارش‌ها (صندوق داخل برنامه) بر پایهٔ JSON در SharedPreferences.
- [x] ذخیره شناسهٔ فرد، عنوان، متن، زمان ایجاد و وضعیت خوانده‌شدن گزارش.
- [x] افزودن صفحهٔ اولیهٔ «گزارش‌ها و حریم خصوصی» به رابط برنامه.
- [x] قفل ایمن گزارش والدین: ثبت نام/رضایت به‌تنهایی شماره را تأییدشده نمی‌کند و اجازهٔ ارسال نمی‌دهد.
- [ ] افزودن فرم اطلاعات تماس ولی و ثبت رضایت صریح و قابل لغو.
- [ ] افزودن تأیید واقعی شماره با OTP از طریق ارائه‌دهندهٔ پیامک؛ تا پیش از آن گزارش والدین غیرفعال بماند.
- [ ] تولید گزارش فقط پس از تصحیح و تحلیل واقعی؛ فعلاً موتور نمره‌دهی/تحلیل هنوز تکمیل نشده است.
- [ ] ساخت اعلان محلی اندروید هنگام ثبت نتیجهٔ واقعی و افزودن مجوز/کانال اعلان مطابق نسخهٔ Android.
- [ ] سیاست نگهداری، حذف و خروجی‌گرفتن از گزارش‌ها و جلوگیری از نمایش گزارش فرد دیگر در دستگاه مشترک.
- [ ] آزمون واحد برای دروازهٔ رضایت/تأیید و آزمون دستی چندحسابی.
- [ ] تصمیم‌گیری جداگانه دربارهٔ همگام‌سازی بین دستگاه‌ها؛ نسخهٔ فعلی محلی است و ارسال از راه دور ندارد.

**مرزهای فعلی:** این مرحله صندوق محلی و کنترل‌های اولیهٔ حریم خصوصی را اضافه کرده است؛ هنوز اعلان سیستمی Android، OTP، ارسال پیامک/ایمیل، موتور تصحیح، و ساخت خودکار گزارش واقعی پیاده‌سازی نشده‌اند. گزارش والدین به‌صورت پیش‌فرض بسته می‌ماند تا تأیید واقعی فراهم شود.

## بانک سؤال و نسخه‌های تصادفی

- [x] افزودن بانک سؤال محلی با متن سؤال، چهار گزینه، پاسخ صحیح و مبحث اختیاری.
- [x] افزودن سازندهٔ سه نسخهٔ تصادفی از بانک: ترتیب سؤال‌ها و ترتیب گزینه‌ها تغییر می‌کند و کلید پاسخ هر نسخه مجدداً محاسبه می‌شود.
- [x] افزودن پیش‌نمایش نسخه‌ها و کلیدهای پاسخ داخل برنامه.
- [ ] جلوگیری از تکرار نسخه‌ها در بانک‌های کوچک و افزودن بذر/شناسهٔ نسخه برای بازتولید دقیق.
- [ ] چاپ برگهٔ کامل هر نسخه و ذخیرهٔ شناسهٔ نسخه در QR پاسخنامه.
- [ ] اتصال کلید همان نسخه به موتور تصحیح و تحلیل؛ تا آن زمان نباید از کلید عمومی آزمون برای نسخه‌های تصادفی استفاده شود.
- [ ] افزودن انتخاب تصادفی از بانک بزرگ‌تر، دسته‌بندی بر اساس مبحث/سختی، و کنترل توازن هر نسخه.

**مرز فعلی:** این قابلیت در نسخهٔ اولیه سؤال‌ها و نسخه‌های تصادفی را در حافظهٔ محلی نگه می‌دارد و پیش‌نمایش می‌دهد. هنوز برگهٔ چاپی نسخه‌بندی‌شده و تصحیح پاسخ‌برگ بر اساس شناسهٔ نسخه متصل نشده است.



## پیاده‌سازی اخیر: هستهٔ محافظه‌کار تشخیص پاسخ

- [x] افزودن `OMRAnswerClassifier` برای طبقه‌بندی چهار امتیاز تاریکیِ نرمال‌شده.
- [x] وضعیت‌های خروجی جداگانه برای پاسخ یکتا، خالی، چندعلامتی و نیازمند بازبینی.
- [x] اعتبارسنجی ورودی‌ها و پرهیز از انتخاب پاسخ در شرایط کم‌اطمینان.
- [ ] اتصال این هسته به استخراج ناحیهٔ حباب از فریم دوربین؛ این کلاس به‌تنهایی تصویر را نمی‌خواند و هنوز موتور کامل OMR محسوب نمی‌شود.
- [ ] تنظیم آستانه‌ها با نمونه‌های واقعی چاپ و دوربین، سپس افزودن آزمون‌های واحد و مجموعهٔ ارزیابی برچسب‌خورده.
