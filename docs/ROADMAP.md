# نقشه راه آزمون‌یار

## مرحله ۰ — دامنه و معیارهای آزمایش
- [x] تعیین نام و جهت‌گیری آفلاین‌محور.
- [x] تعریف رفتار محافظه‌کارانه برای علامت‌های مبهم.
- [x] ثبت نیازمندی اسکن زنده و خودکار بدون دکمه عکس‌گرفتن.
- [ ] تثبیت قالب چاپی پاسخنامه و نمونه آزمایشی.
- [ ] ساخت مجموعه آزمایشی برچسب‌گذاری‌شده با شرایط متنوع.

## مرحله ۱ — پایه اندروید
- [x] ساختار اولیه پروژه اندروید و بیلد خودکار آزمایشی.
- [x] رابط فارسی اولیه.
- [x] تعریف آزمون، تعداد سؤال و ثبت کلید پاسخ در حافظه محلی.
- [x] افزودن وابستگی‌های CameraX و QR decoder آفلاین.
- [ ] پایگاه داده محلی نسخه‌دار و مدل کامل دانش‌آموز/برگه.\n- [x] نمونه اولیه ثبت فهرست دانش‌آموزان به‌صورت آفلاین با شناسه یکتای داخلی (هنوز به QR و چاپ متصل نیست).
- [ ] قواعد نمره‌دهی و آزمون‌های واحد.

## مرحله ۲ — طراحی آزمون داخل برنامه
- [ ] افزودن بخش «ساخت آزمون» با دو روش ورود سؤال: تایپ متن و افزودن عکس از دوربین/گالری.
- [ ] پشتیبانی از متن سؤال، گزینه‌ها، پاسخ صحیح، نمره و توضیح اختیاری.
- [ ] پشتیبانی از سؤال تصویری: تصویر می‌تواند عکس صفحه کتاب، نمودار، فرمول یا شکل باشد؛ تصویر در پیش‌نمایش و خروجی چاپی حفظ شود.
- [ ] ابزارهای پایه تصویر: برش، چرخش و تنظیم محدوده؛ OCR و استخراج خودکار متن قابلیت جداگانه و غیرالزامی است.
- [ ] امکان ترکیب سؤال متنی و تصویری در یک آزمون و جابه‌جایی ترتیب سؤال‌ها.
- [ ] پیش‌نمایش برگه پیش از چاپ و تولید پرسشنامه PDF با صفحه‌بندی قابل خواندن.
- [ ] تولید کلید تصحیح و پاسخنامه استاندارد هماهنگ با همان آزمون.
- [ ] ثبت قالب هر آزمون برای پیوند دادن پاسخ‌ها به سؤال‌ها؛ تصویر سؤال به‌تنهایی برای تشخیص حباب پاسخ استفاده نشود.
- [ ] نگهداری محلی پیش‌نویس‌ها و امکان ویرایش/حذف با تأیید کاربر.

## مرحله ۳ — اسکن زنده و OMR
- [x] پیش‌نمایش پیوسته دوربین با CameraX؛ بدون نیاز به فشردن شاتر.
- [x] تحلیل فریم‌ها در حافظه و خواندن QR آفلاین.
- [x] ثبت شناسه یکتا و جلوگیری از ثبت تکراری در همان آزمون.
- [ ] تولید QR و قالب استاندارد پاسخنامه از داخل برنامه.
- [ ] تشخیص زنده گوشه‌ها/نشانه‌های برگه و اصلاح پرسپکتیو.
- [ ] کنترل وضوح، نور و ثابت‌ماندن برگه؛ فقط پس از عبور از کنترل کیفیت پردازش خودکار شود.
- [x] پردازش فریم دوربین در حافظه؛ تصویر دائمی ذخیره نمی‌شود.
- [ ] خواندن حباب خالی، تک‌پاسخ، چندعلامتی و مبهم.
- [ ] جلوگیری از ثبت دوباره پاسخنامه پس از اتصال OMR به شناسه.
- [ ] صف بازبینی دستی و امکان اسکن مجدد.
- [ ] پشتیبانی از پاسخنامه جداگانه و پاسخ‌های حبابی روی خود پرسشنامه.
- [ ] برای چیدمان معلم‌ساخته، جریان تعریف/تأیید قالب و نگاشت حباب‌ها؛ تشخیص خودکار همه چیدمان‌های دلخواه تضمین نسخه اول نیست.

## مرحله ۴ — نتایج
- [ ] محاسبه نمره طبق سیاست آزمون.
- [ ] جدول نتایج و خلاصه آزمون.
- [ ] ثبت اصلاحات و سابقه تغییر.
- [ ] خروجی CSV/XLSX و PDF به‌صورت محلی.
- [ ] پشتیبان‌گیری و بازیابی با کنترل صریح کاربر.

## مرحله ۵ — اعتبارسنجی و انتشار
- [ ] اجرای موفق بیلد CI و بررسی گزارش خطاها.
- [ ] آزمایش روی گوشی‌ها، دوربین‌ها، نورها و چاپ‌های متفاوت.
- [ ] اندازه‌گیری دقت هر سؤال، دقت کل برگه و نرخ بازبینی.
- [ ] آزمون رگرسیون برای تغییرات الگوریتم تشخیص.
- [ ] ساخت و بررسی APK/AAB امضاشده انتشار؛ بیلد debug را نسخه انتشار معرفی نکنیم.

## مرحله ۶ — نسخه ویندوز
- [ ] استفاده مجدد از قواعد نمره‌دهی و مدل داده مستندشده.
- [ ] پشتیبانی از دوربین یا واردکردن تصویر/PDF.
- [ ] اجرای آفلاین تشخیص و نمره‌دهی.
- [ ] بررسی سازگاری خروجی/ورودی بین اندروید و ویندوز.

## شرط تکمیل هر مرحله
صرفاً سبز شدن کامپایل به معنی تکمیل قابلیت نیست. آزمون خودکار، آزمایش دستی و شواهد قابل بررسی لازم‌اند. هر ادعای دقت باید اندازه و شرایط مجموعه آزمایشی را بیان کند.


## پیاده‌سازی اخیر: ثبت دانش‌آموز و چاپ QR مشترک

- [x] ثبت آفلاین دانش‌آموز با شناسهٔ داخلی یکتا.
- [x] نمونهٔ اولیهٔ چاپ از طریق قابلیت چاپ اندروید: یک صفحهٔ A4 شامل بخش «برگهٔ سؤال» و «پاسخنامه» با QR یکسان برای همان دانش‌آموز و آزمون.
- [ ] اتصال خروجی چاپ به سازندهٔ واقعی برگهٔ سؤال و پاسخنامه؛ فعلاً صفحهٔ چاپ، برگهٔ همراهِ QR است و جایگزین برگهٔ کامل آزمون نیست.
- [ ] اجرای build و آزمایش چاپ روی دستگاه واقعی؛ تا پیش از این آزمایش، موفقیت build/چاپ تأییدشده نیست.

قالب QR فعلی با اسکنر موجود سازگار است: `AZY1|نام دقیق آزمون|شناسه یکتای دانش‌آموز`. نام دانش‌آموز برای نمایش چاپ می‌شود؛ شناسهٔ داخلی، کلید تطبیق است. اگر دو دانش‌آموز نام یکسان داشته باشند، شناسه‌های متفاوتشان مانع یکی‌شدن رکوردها می‌شود.
